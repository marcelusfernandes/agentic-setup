01 / choose deliberately

Which route should own the objective?

Installation does not start a controller. Pick one route for a specific objective and keep the other idle for that work.

Coexistence rule: one coordinator per objective. Codex runs one implementation at a time; Claude may parallelize disjoint tasks under its own contract. A feature added to one route does not imply feature parity in the other.
Primary · Codex

Continuing objective loop

Uses the same skill through a native Codex plugin or project-local installation, with ordinary GitHub issues and explicit human checkpoints.

  • Milestones are optional grouping.
  • Merge permission is distinct from publication.
  • A local review is never a GitHub approval.
Install the native Codex plugin 
codex plugin marketplace add marcelusfernandes/agentic-setup --ref main
codex plugin add agentic-setup@agentic-setup

Start a new thread and invoke $agentic-setup:autonomous-loop. Plugin helpers live beside the loaded skill in Codex's cache, not in the project's .agents directory. See docs/codex-plugin.md for updates; choose one Codex installation source per objective.

Alternative: install into the project 
node scripts/setup-codex.mts --target /path/to/project --dry-run
node scripts/setup-codex.mts --target /path/to/project

This preserves existing project instructions, hooks, CI and local Codex settings.

Opt-in · legacy Claude

Phase-oriented plugin loop

Uses its own commands, strict issue contract, labels, hooks and worktree lifecycle.

  • Milestones organize phases.
  • state:* labels drive this legacy controller.
  • The installer no longer seeds state:done; historically configured repositories may still have it. A closed task issue is the completion convention.

03 / durable records

GitHub is the shared memory

The formats look similar, but their authority is deliberately different.

Objective #120

Outcome and authority

Goal, success criteria, boundaries, permissions, decision makers, plan and checkpoints.

Task #121

A reviewable unit

Acceptance criteria, relevant validation and genuine dependencies.

Checkpoint #122

A human decision

Question, options, recommendation, impact and the tasks it blocks.

How the fictional records connect

Optional grouping Milestone M1

Codex can group work without making the milestone its state machine.

Outcome Objective #120

Owns authority, success criteria, plan and checkpoint list.

Work unit Task #121

Is implemented on codex/task-121.

Delivery PR #44

Merges to the authorized integration branch, then the task can close.

Checkpoint #122 cross-links the hierarchy: it is listed by objective #120 and blocks task #121 until an authorized decision is recorded. After review, checks and merge authority are satisfied, PR #44 may merge; completion evidence then closes the task and advances the objective.

Labels show progress; titles describe work

Codex reconciles labels from GitHub evidence after each durable transition. Keep titles descriptive; checkboxes belong only in acceptance criteria.

state:ready→ state:in-progress→ state:in-review→ state:done

Side paths are state:qa-failed, state:blocked and human. A human request blocks the objective, task or PR it marks and affected dependents. Codex automatically clears it only on answered checkpoints. The separate Claude installer still uses closed issues as completion and does not seed state:done.

Label family Meaning
state:* Codex progress synchronized with labels <objective>. Requires publishing permission; read-only status never writes labels. State labels cannot grant approval; human is an effective stop.
type:* Work classification selected by the coordinator, alongside project-specific scope:*. Preserved during status synchronization; never guessed from titles.
review:approved Not synchronized or trusted by Codex. A fallback in the old Claude policy only; Codex still requires a real GitHub approval and protected checks.

What do installation and merge not authorize?
  • Installing either route does not start an objective or authorize publication, models, production, data access or spending.
  • Starting a loop grants routine publication and validated merge within its boundaries, unless you restrict them. No new confirmation is needed for each PR.
  • Codex defaults to the repository default branch only when the Integration branch heading is omitted. An explicitly empty heading is invalid.
  • Required-rule compatibility is repository-specific: checks and a current independent approval must be enforced by readable server policy before autonomous landing.
  • Never run Codex and Claude coordinators on the same objective.
